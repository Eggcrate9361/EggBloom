## P1 —— 自动化闭环与性能基础

### 4. 图灵测试自动闭环
- **现状**：`turing_feedback` 已能按维度报告"哪里不像、该调注入卡哪条"，
  但需要手动触发，且报告完**不会自动改**。
- **做法**：① 配置 `turing_auto`，蒸馏通过后自动跑盲测；
  ② 报告的 mismatches 直接回写注入卡参数（"长度太长" → 收紧 P90 上限），
  下轮盲测对比是否起效；③ CLI `distill --turing`。
- **价值**：把"像不像"从一次性检验变成持续修正回路；也是唯一能客观
  衡量"蒸馏系统本身好不好"的指标。
- **难度**：中（盲测要花额度，需并入预算系统）

### 5. 语料层缓存
- **现状依据**：`data_collector` 只有配置缓存；每次 `collect()` 全量读
  272KB 落沙 + 解析 4080 行 + 全量画像。现在的 291 条无感，
  **按 1GB 目标这是第一个会死的地方**。
- **做法**：解析结果按「文件 mtime + 大小」做指纹缓存（落沙不可变追加，
  缓存命中率天然高）；风格画像/科学测量按语料指纹缓存，分层存储已有
  读取优化，收集侧补齐。
- **价值**：`render`/`scan`/`distill` 全部提速；1GB 规模的前提。
- **难度**：中

### 6. 增量 LLM 取证
- **现状**：上次 L2 全量 **226k tokens / 18 次调用**；账本只吃增量语料，
  但 LLM 取证仍每层全跑。
- **做法**：账本里"确认 ≥3 次且近 N 轮有证据"的结论跳过重新取证，
  只把新增语料 + 存疑条目交给模型；预算随之动态下调。
- **价值**：连续蒸馏的成本从 O(全量) 降到 O(增量)，长期使用的前提。
- **难度**：中高（要保证不漏新证据的确认机会）

### 7. 定时蒸馏（凌晨窗口）
- 上游额度与 bot 对话共享，实测 TPM 冷却要好几分钟；已建议 04:30 但未建。
- 做法：Windows 计划任务 / EggBloom 内置定时，调 `cli.py distill --consent`。
- 难度：低

## P2 —— 功能深化（都对，但排在闭环之后）

### 8. 按时期注入
- **现状依据**：风格画像已测出漂移（6 月平均 20.9 字 → 7 月 9.5 字），
  注入卡里写着"按时期注入尚不支持"。
- **做法**：注入卡带 `as_of` 时间戳，参数取"最近 N 天"窗口而非全量；
  证据分片按时间过滤已有基础。
- **价值**：模仿"现在的他"而不是"平均的他"。
- **难度**：中

### 9. 时间层节律（L2 即可建）
- **现状依据**：S6 时间层在 L2 显示"很薄"，但确定性数据全有
  （深夜 0-6 点占 33%、时段标准差 7.3h、2.6 个月跨度）。
- **做法**：`psych.observable` / 风格画像的时段数据已算好，
  把它接成 temporal 特征条目（部分已做），补"作息节律"整条。
- **难度**：低

### 10. 对具体人的桶补全
- **现状依据**：`reply_to` 目前 0 条命中——落沙里他的引用大多没带名字。
- **做法**：从 `super_memory` 的会话对象（scope_id）与群消息的
  回复链补 addressee；`relational` 框架已就绪。
- **难度**：中

### 11. 多目标批量蒸馏
- bot 要在群里自然发言，群里每个常发言的人都值得一个人格文件
  （分层存储按 target_id 隔离，已支持）。
- 做法：`cli.py distill --target all --min-messages 50`，扫群成员批量跑。
- **难度**：中（额度调度是主要约束）
