# 发布打包（dist / build）

> 这份文档说明 `E:\EggBloom水星\dist`（对外发布）与 `E:\EggBloom水星\build`（打包暂存）的关系与复现步骤。
> 2026-10-09 首次整理 —— 此前**没有任何打包脚本**，流程是口口相传的。

---

## 1. 三个发行变体的定义

> ⚠ **Full 仅本地自用，不对外分发**（2026-10-18 决定）：它比 Standard 多出的
> 全量二次创作动漫表情包（VRChat / 春日部 / 镇寻），版权来源不明、也不适合放公开仓库。

| 变体 | 内容 | 参考体积（zip） | 暂存目录 |
|---|---|---|---|
| **Lite** | 纯源码树 = `git ls-files` 的全部文件（无 Electron、无 python 运行时） | ~6.2 MB | `build/lite/EggBloom-Lite` |
| **Standard** | Electron 布局（exe/dll/locales/python）+ `resources/app`，其中 `memes` 带 2 个引擎脚本 + 20 张样本（`scripts/make_meme_sample.py`，≤3 MB） | ~215.8 MB | `build/standard/EggBloom-Standard` |
| **Full** | 与 Standard 相同，但 `memes` **全量图片库** | ~706.9 MB（随表情包库增长） | `build/full/EggBloom-Full` |

> 2026-10-30 实测（1.5.10）：Lite 6.2 MB · Standard 215.8 MB · Full 706.9 MB。
> Full 比 1.5.6 那版（534 MB）大，是因为源码库里的表情包库从 294 MB 长到了 495 MB ——
> "全量"的定义没变。

对外文件固定为 `dist/EggBloom-{Lite,Standard,Full}.zip`，**zip 内顶层就是同名文件夹**
（解压即得到一个可直接运行的目录），根目录本身**不改名带版本** —— README 里引用了这三个固定文件名。
版本号写在包内各处的 `VERSION` 里（`release=` 行）。

## 2. 版本号的唯一真相源

**`D:\git\EggBloom\package.json` 的 `version`。**

`scripts/sync-dist.ps1` 每次生成 `VERSION` 时会读它，写出：

```
release=<version>          ← 来自 package.json（唯一真相源）
source_repo=D:\git\EggBloom
source_commit=<short-sha>
sync_date=YYYY-MM-DD HH:MM:SS
```

⚠ 不要手改 `VERSION` —— 它每次同步都会被整个重写，手改的内容会丢。

## 3. 复现步骤

### 一条命令（推荐）

```bash
# 改版本（package.json）→ commit → 打包（顺序不能反，见 §4(2)）
python scripts/pack_all.py
#   同步 Standard/Full + 修剪 Standard 的 memes + git archive 重建 Lite（含手写 VERSION）
#   + 7z 压缩（先 .zip.new 再替换）+ 包内抽检 + 体积汇总
python scripts/pack_all.py --skip-sync   # 暂存目录已同步过，只重建 Lite 与重压缩
python scripts/pack_all.py --only lite   # 只做一个变体
python scripts/pack_all.py --dry-run     # 只打印计划
```

> 2026-10-18 起 `pack_all.py` 做两件事：
> ① 出包前校验 Standard/Full **带桌面壳 exe**（唯一启动入口），缺了就跳过该变体；
> ② 7z 压缩时排除 `__pycache__` / `*.pyc`（Standard 因此少 818 个文件、约 12 MB）。

下面是不依赖该脚本的手工步骤（脚本就是照它实现的）。

### 手工步骤

```bash
# ① 版本号：改 package.json 的 version，然后 commit
#    （不要在这一步之后、打包之前再加提交，见 §4）

# ② Lite：git archive 是最干净的重建方式（只含 tracked 文件，天然无 .git/无运行态）
rm -rf "E:/EggBloom水星/build/lite/EggBloom-Lite"
mkdir -p "E:/EggBloom水星/build/lite/EggBloom-Lite"
git -C /d/git/EggBloom archive HEAD | tar -x -C "E:/EggBloom水星/build/lite/EggBloom-Lite"

# ③ Standard / Full：用现成的同步工具（只增不删，会跳过运行态数据）
#    判据：目标目录下存在 resources/app/webui/webui_server.py
powershell -ExecutionPolicy Bypass -File scripts/sync-dist.ps1 `
  -DistPath "E:\EggBloom水星\build\standard\EggBloom-Standard"
powershell -ExecutionPolicy Bypass -File scripts/sync-dist.ps1 `
  -DistPath "E:\EggBloom水星\build\full\EggBloom-Full"

# ③b ★ Standard 的 memes：先清掉整库，再放 20 张样本（见 §4(0)）
#     sync-dist 的 $dirItems 里有 "memes" → 它会把整个表情包库搬进去（~450MB）。
#     Standard 的定义是"2 个引擎脚本 + 20 张样本（≤3MB）"，不是"只有代码"。
M="E:/EggBloom水星/build/standard/EggBloom-Standard/resources/app/memes"
rm -rf "$M/kagura_nana" "$M/vrchat" "$M/memes/kagura" "$M/memes/vrchat" "$M/memes/zhenxun"
#     pack_all.py 会自动跑这条；只有手工流程才需要手动执行
python scripts/make_meme_sample.py --dst "$M/memes" --count 20
du -sh "$M"    # 期望 ≤ 3M（脚本按 20 张、3MB 预算取样）

# ④ 压缩：7-Zip（C:\Program Files\7-Zip\7z.exe），在**变体的父目录**里执行，
#    这样 zip 内的顶层才是 EggBloom-XXX/ 而不是散文件
cd "E:/EggBloom水星/build/lite"      && 7z a -tzip -mx=5 "E:/EggBloom水星/dist/EggBloom-Lite.zip.new"     "EggBloom-Lite" -y
cd "E:/EggBloom水星/build/standard"  && 7z a -tzip -mx=5 "E:/EggBloom水星/dist/EggBloom-Standard.zip.new" "EggBloom-Standard" -y
cd "E:/EggBloom水星/build/full"      && 7z a -tzip -mx=5 "E:/EggBloom水星/dist/EggBloom-Full.zip.new"     "EggBloom-Full" -y

# ⑤ 确认三个 .new 体积正常后再替换旧包（替换前不要删，压坏了还能回退）
mv -f "E:/EggBloom水星/dist/EggBloom-Lite.zip.new"     "E:/EggBloom水星/dist/EggBloom-Lite.zip"
mv -f "E:/EggBloom水星/dist/EggBloom-Standard.zip.new" "E:/EggBloom水星/dist/EggBloom-Standard.zip"
mv -f "E:/EggBloom水星/dist/EggBloom-Full.zip.new"     "E:/EggBloom水星/dist/EggBloom-Full.zip"
```

## 4. 三个必须记住的坑

### (0) ★ Standard 会被同步工具塞进整个表情包库 —— 必须换成 20 张样本

`scripts/sync-dist.ps1` 的 `$dirItems` 里包含 `"memes"`，它对这个目录是**整目录复制**，
不区分 tracked / 运行态。同步后 Standard 的 `resources/app/memes` 会带上全套图片。

Standard 的定义**不是"只有代码"**：2 个引擎脚本 + 20 张样本（`scripts/make_meme_sample.py`
按 3MB 预算挑，文件名过滤 6 位以上数字），既不是 60KB，也不是全库。

| | 正确内容 | 被同步污染后 |
|---|---|---|
| Standard 的 `resources/app/memes` | 2 个代码文件 + `sample/` 20 张 + `tags.json`（≈3 MB） | **453 MB**（全套图片） |
| Full 的 `resources/app/memes` | 代码 + **全量图片库** | 同左（本来就该有） |

`pack_all.py` 的 `[2]` 步骤会调 `make_meme_sample.py` 自动取样，压缩期再用
`STANDARD_MEMES_EXCLUDE` 排除全库目录；手工流程必须执行 §3 的 ③b，
否则 Standard 会涨到 667 MB。

（代码在**嵌套层** `memes/memes/`，不是 `memes/` —— `git ls-files memes/` 只有
`memes/memes/meme_engine.py`、`memes/memes/tag_memes.py`。`tags.json` 由取样脚本生成，不入库。）

### (1) `7z a` 对已存在的 zip 是「增量添加」，不是重建

它**不会删掉**目标包里已经不存在于源目录的条目 → 直接压到 `dist/EggBloom-XXX.zip` 会让
旧文件永远留在包里。**必须先输出 `.zip.new` 再替换。**

### (2) 打包之后不要再新增提交

包里 `VERSION` 记的是 `source_commit`。打包完成后再 commit，包立刻"落后一个提交"，
`scripts/activate.py --check-only` 会报「同步落后」。
**顺序：改版本 → commit → 同步 → 压缩。**（想补文档也放在最前面。）

## 6. 常见卡点（本机实测）

### `[safe-delete] SAFE_DELETE_BULK_CONFIRM_REQUIRED`

本机安全策略会拦下**单次超过 50 个文件**的递归删除。打包流程里有两个地方会撞上：

| 步骤 | 影响文件数 | 表现 |
|---|---|---|
| `[2]` 裁剪 Standard 的 memes 图库 | ~270 | 脚本中断，包没出 |
| `[3]` Lite 暂存树重建 | ~390 | 脚本中断，包没出 |

**应对**（任选其一）：

1. 手动先删（Standard）：确认目标在 `build\standard\...\resources\app\memes\` 下后授权删除；
   源码库与 Full 包不受影响，随时可 `sync-dist.ps1` 重新同步回来。
2. 改名让路（Lite）：`rename EggBloom-Lite EggBloom-Lite.old` —— rename 不算删除，
   脚本会重建干净目录，再 `pack_all.py --skip-sync` 续跑。
3. 改流程：**已采用** —— Standard 不再删暂存，改用 7z `-xr!` 在压缩时排除图库目录
   （`STANDARD_MEMES_EXCLUDE`），删文件的麻烦和风险一起消失。

> 2026-10-18 实际走的是「1 + 2」出第一版包；随后发现陈旧文件问题（见下），
> 改为重建干净暂存树 + 压缩期排除，第二轮 4 分 38 秒出三个包。

## 7. ★★ 陈旧文件：比隐私更隐蔽的那一类

`sync-dist.ps1` 只增不删（防止误删用户运行态），于是**几个月前的旧文件会一直躺在暂存树里
被打进包**。2026-10-18 在 Standard 里实测翻出：

| 文件 | 问题 |
|---|---|
| `webui/webui_artistic_v3.html` | robocopy `/XF webui_artistic_v3.html` 按**文件名全局排除**，这份从没同步过 → 一直停在 8/16，里面是真实 QQ 号与昵称 |
| `plugins/conversation_state/<QQ>.json` | **文件名本身就是 QQ 号**（会话状态） |
| `personality.txt` / `plugins/personality.txt` | 个人人格 |
| `message_router.py`、`*.pre-redesign-backup.html`、根目录重复副本 | 旧布局残留 |
| `_font_audit.png`、`_parity_report.json`、`webui_v4_standalone.html` | 开发产物（git 忽略了，但 robocopy 照搬） |

### 三道防线（已落地）

1. `sync-dist.ps1` 收尾清理运行态残留：`plugins/state`、`plugins/conversation_state`、
   `_font_audit.png`、`_parity_report.json`；`webui_v4_standalone.html` 进排除名单。
2. v3 **取消排除**（否则永远同步不进去），根目录重复副本交给陈旧审计兜底。
3. `pack_all.py` 的**陈旧文件硬闸**：出包前比对「暂存树有、源码库没有」的文件，
   有就拒绝出包（要强打加 `--allow-stale`）。

### 重建干净暂存树（本机不让批量删，所以用改名）

```text
① 把 <包>\resources\app 改名为 app.old-1        （exe / python / locales 留在包根，不动）
② 新建 <包>\resources\app\webui\ 并放一个 webui_server.py  ← sync-dist 的目录校验需要它
③ sync-dist.ps1 -DistPath <包>                    （重建干净树）
④ 补运行时资产：BGE 模型 + LiGGUF 许可（Full 另加表情包图库）
⑤ 把 app.old-1 移出包根 —— 忘了这步，Standard 会从 212MB 涨到 259MB
```

第 ⑤ 步对应 `SEVENZ_EXCLUDES` 里的 `-xr!*.old` / `-xr!*.old-*` 兜底。
