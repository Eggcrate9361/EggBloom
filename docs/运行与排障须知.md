# 运行与排障须知

> 适用：EggBloom Desktop 的**桌面壳**（Electron 那份）双击没反应、打不开、开一半消失。
> 不适用：后端 python 起不来（那是另一类问题，看第 5 节日志）。
> 最后更新：2026-11-03（由一次真实故障倒推出来的，见第 3.1 节）

---

## 0. 一句话结论

**"双击没反应" 九成不是程序坏了，是它根本没被允许启动。**
先别重装、别换 exe、别改代码 —— 按第 2 节三行命令看清它在哪一步断的。

---

## 1. 三条命脉

| 东西 | 位置 |
|---|---|
| Electron 启动日志（壳自己写的） | `%APPDATA%\eggbloom-desktop\server-spawn.log` |
| 后端日志 | `<安装目录>\resources\app\data\logs\qq_bot.log` |
| 后端端口 | 8080（被占会自动顺延，实际端口写在 `<安装目录>\last_port.txt`） |

判断"壳有没有起来"，只看 `server-spawn.log` 有没有新行。
它一启动就会写 `server ready (first wait)` 和 `Tray created OK`。
**一行没写 = Electron 还没跑到 JS，别去查 python。**

---

## 2. 三行自检

```powershell
# ① 进程在不在
Get-Process | Where-Object { $_.ProcessName -match "EggBloom" } | Format-Table Id,MainWindowTitle

# ② 后端在不在
Get-NetTCPConnection -LocalPort 8080 -State Listen

# ③ 壳的日志有没有新行
Get-Content "$env:APPDATA\eggbloom-desktop\server-spawn.log" -Tail 5
```

三种结果：

- ①②③ 全空 → 进程**根本没创建或秒退**，往下看第 3 节
- ① 有进程、③ 没新行 → 卡在 Electron 引导，看第 3.1 / 3.4 节
- ① 有进程、② 没端口 → 壳起来了但后端没起来，看第 5 节

## 3. 已确诊的坑

### 3.1 ★ 目录被打上「低完整性」标签（2026-11-03 实际翻车）

**症状**：双击后什么都没发生。没有窗口、没有报错、没有日志新行，
进程连 1 秒都活不到，退出码 0。看起来完全像"程序坏了"。

**判断**（一行就够）：

```powershell
icacls "<安装目录>\EggBloom Desktop.exe"
```

看到这行就是中招：

```
Mandatory Label\Low Mandatory Level:(I)(NW)
```

正常的应该是 `Medium Mandatory Level`，或者干脆没有这一行。

**为什么致命**：低完整性（Low IL）的进程没有权限访问用户目录和 `%APPDATA%`。
Electron 启动第一件事就是在那儿建 userData，建不了就直接退，
而且**退得干干净净** —— 不写日志、不弹窗、不留痕迹。

**修复**（管理员）：

```powershell
# 把整棵树改回 Medium（会把 Low 标签从所有文件上剥掉）
icacls "<安装目录>" /setintegritylevel (OI)(CI)Medium /t /c /q

# 父目录也要改，否则以后新建的文件继续继承 Low
icacls "<安装目录的上级>" /setintegritylevel (OI)(CI)Medium
```

**谁干的**：沙盘 / 低权限运行 / 文件保护 / 加密盘这类工具。
它们除了加 Low 标签，通常还会附赠一个 ACL 拒绝项：

```
Everyone  DeleteSubdirectoriesAndFiles  DENY
S-1-4-<一串数字>  Write, Delete, Synchronize  ALLOW
```

其中 `S-1-4-...` 是很典型的沙箱 SID。**这条 SID 用 icacls 删不掉**（会提示
`Successfully processed 0 files`），但删掉 `Everyone` 的 DENY 就够用了：

```powershell
icacls "<安装目录>" /remove:d Everyone
```

**排查时最坑的一点**：把文件**复制**到别的目录就能跑（复制会继承新位置的 ACL，
Low 标签自然没了），于是很容易误判成"exe 坏了"。本次就是这么绕了一大圈。
**复制能跑、原地不能跑 = 十有八九是 ACL/完整性标签。**

### 3.2 SmartScreen 拦未签名 exe

**症状**：蓝底大字"Windows 已保护你的电脑 / 阻断了无法识别的应用启动"。

**原因**：exe 没有代码签名。这不是故障，是设计。

**处理**：点「更多信息」→「仍要运行」（有的版本直接有「仍要运行」按钮）。
按文件记住，同一份文件不再问。

**根治**：买代码签名证书。自签证书没用，仍然会提示。

**注意**：过了这一关**不代表**能起来 —— 本次在点完「仍要运行」之后，
才暴露出 3.1 那个问题。两道坎要分开看。

---

### 3.3 单实例锁：拿不到锁会**静默退出 0**

`main.js` 第 8 行：

```js
const gotLock = app.requestSingleInstanceLock();
if (!gotLock) { app.quit(); }
```

**症状**：和 3.1 几乎一样（秒退、无日志、退出码 0），
区别是**任务管理器里能看到另一个 EggBloom 进程**。

**判断**：

```powershell
Get-CimInstance Win32_Process | Where-Object { $_.ExecutablePath -like "*EggBloom*" } |
  Select-Object ProcessId, ExecutablePath
```

**处理**：关掉旧实例。如果是崩溃残留，`Stop-Process -Force` 清掉即可。

---

### 3.4 `ELECTRON_RUN_AS_NODE` 被继承

**症状**：exe 立刻退出，或报 `bad option: --xxx`（这是 **Node 的**报错格式，不是 Electron 的）。

**原因**：如果这个 exe 是从**另一个 Electron 进程**里启动的
（脚本、调试器、某些 IDE），环境变量会被继承。
`ELECTRON_RUN_AS_NODE=1` 一设，Electron 就退化成纯 Node —— 没有脚本可跑，直接退出。

**判断**：

```powershell
cmd /c "echo [%ELECTRON_RUN_AS_NODE%]"
```

**处理**：真正删掉它，用 `set X=` 设成空串**没用**（Electron 判断的是"存不存在"）：

```powershell
Remove-Item Env:ELECTRON_RUN_AS_NODE
```

用户双击（资源管理器启动）不受此影响，这个坑只在脚本/自动化里出现。

---

### 3.5 8080 被占

后端会**自动顺延端口**并写 `<安装目录>\last_port.txt`，壳会读这个文件跟上。
所以"8080 没监听"**不等于**后端没起来，先看 `last_port.txt`。

## 4. 诊断顺序（照这个走，别跳）

```
双击没反应
  ├─ 有没有 SmartScreen 蓝屏？        → 3.2
  ├─ 任务管理器有 EggBloom 进程吗？
  │    ├─ 有 → server-spawn.log 有新行吗？
  │    │        ├─ 有 → 壳正常，是后端问题 → 第 5 节
  │    │        └─ 无 → 3.1 / 3.3 / 3.4
  │    └─ 无 → icacls 查完整性标签（3.1）→ 查是不是从脚本启动的（3.4）
  └─ 全都不对 → 拿 <安装目录> 的 exe + 运行时文件复制到 D:\ 根下试跑
                · 复制到别处能跑 = ACL/完整性标签（3.1）
                · 复制到别处也不能跑 = exe 或运行时真坏了
```

## 5. 后端起不来（不是壳的问题）

```powershell
cd "<安装目录>"
.\python\python.exe resources\app\webui\webui_server.py
```

前台跑能看到真实报错（壳是 `stdio: ignore`，把它藏起来了）。
起不来最常见的两种：端口全占满、依赖缺失。

**手工起后端是有效的降级方案**：壳只是个窗口，界面在 `http://localhost:8080`，
浏览器打开功能一样全。壳坏了不影响用。

---

## 6. 不要做的事

1. **别重装先**。3.1 那种情况重装到同一个目录照样中招，除非换个父目录。
2. **别无差别杀 python/node**。`main.js` 自己清理进程时都只按"应用目录"过滤，
   手工作业也请保持这个分寸 —— 机器上可能同时挂着别的 QQ / 别的 python。
3. **别用 `Start-Process` 抓这个 exe 的输出**。它会挂住（子进程继承了管道），
   而且 Electron 在 stdout 被重定向时可能直接报 ICU 错误，得到的是**假故障**。
   要抓日志就让它自己写文件。
4. **别把单实例竞态当成崩溃**。先看有没有旧进程。
5. **别忽略 `Mandatory Label` 这一行**。它通常不出现在排查清单里，但它能一秒定位问题。
