# 排障手册（证据优先）

## 铁律
1. **先看证据再谈假设**：日志文件、接口返回、数据库/文件的实际内容 —— 一条实证胜过十次猜测
2. **先复现再修复**：不能稳定复现的 bug 修了等于没修
3. **一次只改一件事**：改动捆在一起 = 永远不知道是哪一处生效的

## 步骤
1. 现象 → 找到**第一手证据**（日志行 / 返回值 / 文件内容），贴出关键行
2. 最小复现：用最小的输入撞出同样的问题
3. 二分定位：把链路对半切开，判断问题在哪半边，重复
4. 修完**必须验证**：用第 2 步的复现方法证明修好了；顺手补一条防回归的检查

## 常见坑
- "搜索没结果"先怀疑搜索面太窄（目录/字段名/大小写），再怀疑真没有
- 改动后没生效 → 先确认进程是否重启、缓存是否失效、配置是否热加载
- 时序类问题（竞态/缓存窗口）静态检查抓不到，要用计时测试去撞
