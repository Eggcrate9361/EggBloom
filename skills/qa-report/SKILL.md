# 问题报告格式

每条问题按下面五段说，缺证据的段落就明说"未确认"：

1. **现象** —— 用户看到什么（一句话）
2. **根因** —— 为什么（引用代码行/日志行作为证据）
3. **修法** —— 改了什么（文件 + 位置 + 思路）
4. **验证** —— 怎么证明修好了（实测数字/测试结果）
5. **遗留** —— 顺带发现但没修的、需要主人拍板的

## 要求
- 拒绝"应该/大概/可能是"这类没有证据的表述；有假设就标注"假设，待验证"
- 数字优于形容词（"455ms 落地"优于"明显变快"）
- 汇报里区分"已修"与"已定位未修"，绝不混在一起
